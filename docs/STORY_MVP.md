# Сюжетный MVP «Немой лифт»

## Как устроена игра

Клиент показывает только действия, которые уже следуют из опубликованных фактов. В начале доступны две независимые проверки: привод и силовая линия. Общий прогресс работы складывается из минутных вкладов всех игроков. Завершение создаёт факт и, если событие достаточно значимо, запись летописи с реальными участниками.

Когда подтверждены износ привода и ручное отключение, сервер один раз публикует сводную главу и открывает Заводское вече на 24 часа. У каждого аккаунта один равный голос; голос можно заменить до закрытия. Кворума нет. При ничьей или отсутствии голосов применяется безопасный вариант «Продолжить расследование». Результат открывает только соответствующую ветку работ.

| Решение вече | Следующие работы | Финал |
| --- | --- | --- |
| Продолжить расследование | след доступа → нижний пролёт → ремонт → проверочный пуск | лифт возвращён в ограниченный режим |
| Запустить немедленно | снять блокировку → запустить изношенный привод | кабину удерживают аварийные ловители |
| Законсервировать шахту | запечатать шахту → собрать обходную линию | снабжение идёт по сервисному пути |

Будущие шаги не выдаются клиенту. Интерфейс получает 1–3 ближайшие работы, текущую общую цель, опубликованные факты и уже состоявшиеся главы.

## Компоненты и данные

- `src/story/domain.ts` — авторские определения работ, условия, факты, развилки и тексты летописи.
- `server/store.mjs` — транзакции SQLite и единственный источник истины общего мира.
- `server/app.mjs` — HTTP API; все сюжетные и пользовательские маршруты требуют личности.
- `server/auth.mjs` — HMAC-проверка Telegram `initData`; тестовые заголовки доступны только вне production.
- `src/story/repository.ts` — общий API-клиент и явно помеченная локальная демонстрация.
- `src/story/useStory.ts` — загрузка, обновление, кэш для чтения без сети и мутации.

Основные таблицы: запуск эпизода, игроки, участники, экземпляры работ, идемпотентные вклады, факты мира, события, записи летописи, вече и бюллетени. Стабильный `eventId` не позволяет повторному запросу начислить прогресс или XP дважды. Уникальные ключи не позволяют повторно создать факт, главу или итог вече.

## Соответствие старого и нового интерфейса

| Старый элемент | Новая роль |
| --- | --- |
| линейные «миссии» и проценты эпизода | причинно доступные работы без спойлеров будущего |
| локальные наряды | общие работы со вкладом игрока |
| статические новости | летопись из подтверждённых событий |
| заранее известные последствия выбора | аргументы до голосования, результат после закрытия |
| вымышленные рабочие в локациях | реальные участники в опубликованных докладах |
| localStorage как мир | серверная SQLite; localStorage хранит UI и отдельное демо |

Старые сохранения интерфейса не интерпретируются как факты общего мира. При первом запуске новая версия сохраняет резервную копию и объясняет переход.

## Добавление сюжетного материала

1. Добавьте работу в `workDefinitions` с художественным названием, локацией, ближайшим результатом и условием `visibility`.
2. Опишите подтверждаемые факты. Формулировка должна отделять наблюдение от гипотезы: ручная команда подтверждает вмешательство, но сама по себе не доказывает саботаж.
3. Значимому результату добавьте `chronicle`; рядовые минутные действия остаются в личном дневнике.
4. Свяжите следующую работу только через факт, завершение или результат вече. Не передавайте скрытые определения клиенту.
5. Для новой развилки добавьте авторский финал и тесты доступности каждой ветки, повторной доставки и граничного времени.

Иллюстрации лежат в `public/story`. Поле `illustrationId` должно иметь соответствующий файл и содержательный `alt` в клиентском реестре.

## Развёртывание

API запускается командой `node server/index.mjs` или контейнером из `Dockerfile`. Для SQLite требуется постоянный том; несколько реплик без общей БД использовать нельзя. Разрешите CORS только адресу клиента, задайте `TELEGRAM_BOT_TOKEN` как секрет и не включайте `ALLOW_DEV_AUTH` в production.

GitHub Pages собирает клиент с repository variable `STORY_API_URL`. Без неё опубликованная версия остаётся локальной демонстрацией и показывает это постоянной плашкой. После развёртывания проверьте `/api/health`, вход из Telegram, двух разных пользователей, замену голоса и сохранение после рестарта контейнера.
